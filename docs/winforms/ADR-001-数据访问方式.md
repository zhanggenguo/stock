# ADR-001：WinForms 查询基础数据的数据访问方式

- 日期：2026-11-25
- 状态：已接受
- 决策范围：Phase 1 基础数据查询（.NET Framework 4.6 WinForms）

## 背景

要创建一个 Framework 4.6 的 WinForms 桌面程序，用于查询已入库的上市公司基础数据（5108 家）。数据来源有两种选择：

- A：WinForms 直接用 MySQL 连接串查询 `stock_analysis` 库；
- B：WinForms 调用已有的 .NET 10 API 项目（`StockAnalysis.Api`）。

用户没有相关架构经验，需要明确建议与理由。此决策会决定后续所有阶段客户端的接入方式，因此先固定下来。

## 决策

**选择 B：调用现有 API，WinForms 不直接连接数据库。**

数据库连接串、SQL、表结构知识只保留在 .NET 10 服务端；WinForms 只负责展示和交互，通过 HTTP 调用 API。

## 理由

1. **凭据安全**：当前 MySQL 使用 `root` 账号。直连意味着把 `root/12345678` 写进每台客户端的配置或代码里，程序一旦拷走就算泄露。API 方案下凭据只留在服务端，客户端只知道一个本机 HTTP 地址。
2. **查询逻辑单点维护**：搜索（名称/代码/全称模糊匹配）、统计、字段映射这些逻辑已经写在 API 里。直连会在客户端重写一遍 SQL，以后改口径要改所有客户端；走 API 则改一处即可。
3. **表结构变化被隔离**：数据库已经采用 SQL 脚本版本化迁移（V001/V002），以后加字段、加索引会继续新增版本。API 屏蔽了这些变化，只要接口返回结构不变，WinForms 不用跟着改；直连会让界面直接绑定表结构，迁移一次就可能崩一次。
4. **与第二阶段衔接**：龙头企业识别、业务构成、政策权重、估值这些计算会放在服务端统一产出。WinForms 现在只做"查询展示"，第二阶段直接加接口调用即可；直连模式会把 UI 锁死在原始表上，到时候要返工。
5. **已有现成投资**：API 已完成并验证（5108 家入库、5 家字段抽查一致、迁移版本全部 applied）。启动成本只是一条 `dotnet run` 命令，不需要重写数据访问层。

## 代价与缓解

| 代价 | 缓解方式 |
|---|---|
| 需要先启动 API 服务才能查询 | 提供一键启动脚本；WinForms 启动时检测服务并给出明确提示，而不是崩溃 |
| 多一层 HTTP，性能略低于直连 | 本场景是低频人工查询（单次几十到几千行），网络开销可忽略 |
| 客户端依赖接口契约 | 接口路径和响应模型写入本文与复现手册，变更时同步版本号 |
| API 服务停止时不可用 | 界面显示"服务未启动"及启动命令；数据本身仍在 MySQL，不会丢失 |

## 明确不做的理由（直连）

直连唯一的优点是"不用启动服务"，但代价是把数据库最高权限账号分发到客户端、把查询与表结构写死在界面里。对一个还要继续演进的系统，这个便利不值得。

## 验证方式

- WinForms 能查询、筛选、查看详情，数据来自 API 而非本地 SQL；
- 客户端工程中搜索不到 MySQL 连接串、账号密码或 `SELECT` 语句；
- 停掉 API 后界面给出可读的错误提示，而不是抛异常崩溃；
- 按复现手册重建后，行为与当前程序一致。
