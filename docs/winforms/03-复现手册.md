目标：按本文操作，可从零重建出与当前完全相同的 Framework 4.6 WinForms 程序。
配套文件：[ADR-001](ADR-001-数据访问方式.md)（为什么走 API）、[02-开发日志](02-开发日志.md)（过程留痕）。

## 1. 前置条件与验证

本机环境（2026-11-25 实测）：
- .NET SDK 10.0.103（`dotnet --version`）；
- VS 18 Enterprise 自带 MSBuild；
- **本机没有 .NET Framework 4.6 targeting pack**（Reference Assemblies 只有 v3.0/v3.5）。


## 3. 手工逐步重建（等价步骤）

### 3.1 项目文件 `StockQuery.WinForms.csproj`

SDK 风格项目，目标 `net46`；`OutputType=WinExe`；`LangVersion=7.3`（Framework 4.6 兼容的语法上限）。
引用 `System.Windows.Forms`、`System.Windows.Forms.DataVisualization`（折线图控件）、`System.Drawing`、`System.Net.Http`；NuGet 包见第 0 节；`appsettings.json` 复制到输出目录。图表控件来自 `Microsoft.NETFramework.ReferenceAssemblies.net46` 包内的 `System.Windows.Forms.DataVisualization.dll`，无需额外安装。

> 关键：不用传统 `. designer.cs` 设计器文件，界面全部手写代码，保证文档/脚本能逐字重建。

### 3.2 配置文件 `appsettings.json`

只保存 `ApiBaseUrl`，默认 `http://localhost:5000`（2026-11-25 与重建基准统一）。**禁止出现数据库地址、账号、密码**——这是 ADR-001 的硬约束。

### 3.3 `Program.cs`

`[STAThread]` 入口；启用视觉样式；读配置创建 `ApiClient`；配置错误时 MessageBox 提示后退出，不抛未处理异常。

### 3.4 `Models.cs`

定义 `Company`（35 个字段）、`MarketHistory`（日行情/市值，对应 `/api/market/daily`）、`InfoSource`（信息来源条目）、`IndustryNode`、`Stats`、`ExchangeCount`、`Health`、`MigrationInfo`，用 `[JsonProperty]` 显式映射 API 的小驼峰字段名。Company 字段数量必须与 API 详情返回的 35 个字段一致（实测已核对）。`MarketHistory` 另有两个只读计算属性 `TotalMarketCapYi` / `FloatMarketCapYi`，把服务端的“元”换算成表格展示用的“亿元”。IndustryNode 对应 `/api/industry/tree` 的 7 个字段。

### 3.5 `ApiClient.cs`

- `ClientConfig.LoadApiBaseUrl()`：从程序目录读 `appsettings.json`；
- `ApiClient` 封装 8 个 GET：`/health`、`/api/company/stats`、`/api/company?keyword=&exchange=&limit=&industryId=`、`/api/company/{id}`、`/api/market/daily?companyId=&limit=`、`/api/info-source`、`/api/migrate/status`、`/api/industry/tree?scheme=`；另有 4 个写操作（`CreateInfoSource` / `UpdateInfoSource` / `DeleteInfoSource` 走 `Send<T>` 发送 POST/PUT/DELETE JSON，204 空响应返回默认值）；`Search` 有重载（带/不带 industryId），URL 用 `Uri.EscapeDataString` 转义含 `/` 的行业路径 ID；
- 用 `HttpClient` 同步等待（`GetAwaiter().GetResult()`），避免 async UI 复杂度；
- 把网络异常/超时/JSON 解析异常包装为 `ApiException`，给出"请先启动 .NET 10 服务"等可读提示。

### 3.5.1 设计器可编辑结构（重要）

三个窗体（`MainForm`、`DetailForm`、`InfoSourceForm`）都拆成 `Xxx.cs`（业务）+ `Xxx.Designer.cs`（界面）两部分，可在 VS 设计器中直接打开可视化调整（2026-11-25 改造，此前全部代码手写在 `BuildUi()` 里，设计器只显示空白窗体）。必须同时满足以下条件，缺一不可：

1. 窗体类声明为 `public partial class`，**不要加 `sealed`**（设计器需要派生宿主机）；
2. 必须提供**无参构造函数**，内部只调用 `InitializeComponent()`，不得访问 `_api`（设计器不注入依赖）；
3. 带依赖的构造函数（如 `MainForm(ApiClient api)`）调用无参构造，再注入依赖、挂业务逻辑；
4. 所有控件是 `private` 字段，字段声明与 `InitializeComponent()` 都放在 `.Designer.cs`；
5. `.csproj` 里为窗体注册 `<SubType>Form</SubType>`、为设计器文件注册 `<DependentUpon>主文件.cs</DependentUpon>`，VS 才会显示"设计"视图并把两个文件嵌套在一起；
6. Load 事件处理里判断 `if (_api == null) return;`，设计器预览时不请求数据。

**调整界面的正确做法**：在 VS 中双击 `MainForm.cs` → 切到"设计"视图 → 拖动控件，保存后设计器自动重写 `MainForm.Designer.cs`；不要用代码编辑器手改 `InitializeComponent()`。改完运行 `python tools/_gen_rebuild.py` 同步重建基准。

`DetailForm` 顶层是 `_tabs`（TabControl），第一页 `_tabPrice` 放 `_gridMarket`（历史行情表格）、`_chart`（收盘价折线图）与 `_lblPriceHint`（空数据/错误提示）；第二页 `_tabCompany` 放滚动容器 `_panel`。35 个公司字段文本框仍按数据动态生成（字段太多，不适合设计器拖控件），设计器里可直接选中并调整 Tab、表格列、图表与关闭按钮。

### 3.6 `MainForm.cs`

左侧：`TreeView` 行业树（东财 EM 三级），根节点"全部公司"，节点文本 `名称 (totalCount)`；点击节点设置筛选行业，"全部公司"按钮重置；计数口径为含后代。树与列表之间是标准 `Splitter`（`Dock=Left`、4px、`MinSize=180`、`MinExtra=420`），运行时可拖动改变树面板宽度；对应的 `Controls.Add` 顺序必须为 `_body`(Fill) → `_splitter`(Left) → `_treePanel`(Left) → 顶部/底部面板，否则分隔条会出现在错误一侧。
顶部：关键字输入、交易所下拉（全部/SSE/SZSE/BSE）、条数（10~5000）、查询/全部公司/刷新统计/迁移版本四个按钮；最右侧从右向左新增工具栏按钮，当前第一个是「信息来源」（`_btnInfoSources`，`Location=(1064,10)`），点击弹出 `InfoSourceForm`。
中部：`DataGridView`（只读、整行选择、10 列，隐藏 ID 列），绑定 `ContextMenuStrip`（菜单项“详情”）；双击行或右键点“详情”都调用 `OpenDetail(rowIndex)`。右键时先用 `CellMouseDown` 把 `CurrentCell` 落到被点中的行，避免菜单作用到上一行。
底部：`StatusStrip` 显示当前行业、本次条数、库内总数、各交易所数量、最近采集时间。
加载流程：`CheckHealth()` → `LoadIndustryTree()` → `RefreshStats()` → `Search()`；树加载失败弹提示但不阻断列表查询；任何 `ApiException` 都 MessageBox 提示，不崩溃。
树的首行可见性：初始化期间用 `_suppressTreeSelection` 屏蔽 `AfterSelect` 重入；`ExpandAll()` 后设 `SelectedNode`，再调用 `PinTreeTop()` 把 `TopNode` 固定为根节点；`MainForm_Load` 全部布局完成后再固定一次。两个面板 Label 必须 `AutoSize = false`，否则高 DPI 下 Dock 几何不确定，首行可能被截掉上半部分（2026-11-25 已实测修复）。

### 3.7 `DetailForm.cs`

运行时构造函数 `DetailForm(ApiClient api, Company c)` 先填公司资料，再调 `GetMarketDaily(companyId, 500)` 加载历史行情：表格数据源直接绑定返回的倒序列表；折线图反向遍历，按时间正序画 `Series["收盘价"]` 的 `Points.AddXY(TradeDate, Close)`。无记录或请求失败时用 `_lblPriceHint` 显示可读提示，不弹窗打断用户。第二页以 Label + 只读 TextBox 展示公司完整字段；简介、经营范围、地址、来源链接用多行框；`AutoScroll=true`；底部关闭按钮始终可见。

### 3.8 `InfoSourceForm.cs` / `.Designer.cs`

顶部 `_filterPanel` 为「分类筛选」下拉（`_cboFilterCategory`，"全部分类" + 11 个章节名，客户端过滤）；`_grid` 列出 ID / 分类 / 类型 / 名称 / 定位描述·说明 / 重点查询内容·组合·目的 / 网页地址 / 更新时间；下部 `_editPanel` 提供分类、类型（网站/组合/模板/笔记下拉 `_cboEntryType`）、名称、网页地址、定位描述、重点查询内容六个输入项与新增 / 保存 / 取消编辑 / 删除 / 关闭按钮，以及 `_hint` 状态提示。选择一行（或双击）自动回填编辑区并切换到更新模式；「新增」清空进入新增模式；「保存」按模式调用 `CreateInfoSource` 或 `UpdateInfoSource`（界面类型名映射 API 值：网站=site、组合=combo、模板=template、笔记=note）；「删除」二次确认后调用 `DeleteInfoSource`；每次写操作后自动 `LoadList()` 刷新。构造函数无参版本只调 `InitializeComponent()`，`Load` 里判断 `_api == null` 直接返回，保证设计器可预览。

数据库表与服务端契约见 [docs/info-source-信息来源目录.md](../info-source-信息来源目录.md)（V005+V006 迁移、条目类型、字段校验、文档导入链路与验收证据）。数据库已导入《投资研究信息来源网站清单》全部 95 条信息。

## 4. 接口契约（WinForms 依赖的全部接口）

| 调用 | 路径 | 用于 |
|---|---|---|
| `CheckHealth` | `GET /health` | 启动时确认 API 与 MySQL 可用 |
| `GetStats` | `GET /api/company/stats` | 状态栏总数与分布 |
| `Search` | `GET /api/company?keyword=…&exchange=…&limit=…&industryId=…` | 主列表，industryId 按行业及子行业筛选 |
| `GetCompany` | `GET /api/company/{companyId}` | 双击/右键“详情”的公司档案 |
| `GetMarketDaily` | `GET /api/market/daily?companyId=…&limit=500` | 详情第一页历史股价表格与折线图 |
| `GetMigrations` | `GET /api/migrate/status` | "迁移版本"按钮 |
| `GetIndustryTree` | `GET /api/industry/tree?scheme=EM` | 左侧行业树 |
| `GetInfoSources` | `GET /api/info-source` | 信息来源清单 |
| `CreateInfoSource` | `POST /api/info-source` | 新增信息来源 |
| `UpdateInfoSource` | `PUT /api/info-source/{id}` | 更新信息来源 |
| `DeleteInfoSource` | `DELETE /api/info-source/{id}` | 删除信息来源 |

服务端接口定义见 `docs/phase1-公司基本信息.md` 第 7 节；信息来源的契约见 `docs/info-source-信息来源目录.md` 第 3 节。

## 7. 变更与留痕规则

1. 任何代码变更先改 `src/winforms/...`，再运行 `python tools/_gen_rebuild.py` 同步基准；
2. 每次变更在 `02-开发日志.md` 追加一条：日期、改动、理由、验证命令与结果；
3. 若数据访问方式发生变更（例如改为直连），必须先新建 `ADR-002` 并标注 ADR-001 被取代；
4. 接口契约变化时，同步更新本文第 4 节和 `Models.cs`，并重新执行第 5 节验收。
