# 01 — 总体架构设计

## 1. 架构分层

采用"数据流水线 + 应用服务"的分层架构，共 6 层。每层只依赖下一层的稳定接口，任何一层可单独重跑。

```
┌──────────────────────────────────────────────────────────────┐
│ L6 应用层   Web 工作台 / 个股档案 / 行业政策看板 / 估值对比 / 预警推送 │
├──────────────────────────────────────────────────────────────┤
│ L5 服务层   查询API · 观点服务 · 证据链服务 · 人工复核工作台        │
├──────────────────────────────────────────────────────────────┤
│ L4 计算层   龙头识别 · 业务构成解析 · 政策打分 · 价值评估 · 观点合成  │
├──────────────────────────────────────────────────────────────┤
│ L3 存储层   PostgreSQL(结构化) + 对象存储(原始文件) + Redis(缓存/锁)  │
├──────────────────────────────────────────────────────────────┤
│ L2 采集层   连接器(东方财富/巨潮/交易所/政策源) · 限流 · 重试 · 去重  │
├──────────────────────────────────────────────────────────────┤
│ L1 调度层   定时触发 · 依赖DAG · 幂等 · 失败告警 · 数据质量门禁      │
└──────────────────────────────────────────────────────────────┘
```

**数据流向**：`L1 触发 → L2 采集（原始层落盘）→ L3 清洗入库 → L4 计算产出信号 → L5 组装观点/证据 → L6 展示`，L3 的质量门禁不通过则阻断 L4。

## 2. 模块划分与职责

| 模块 | 职责 | 关键输出 | 不负责 |
|---|---|---|---|
| `connector/` | 对接各数据源，处理格式差异、分页、限流 | 原始 JSON/PDF/HTML + 采集元数据 | 业务清洗、打分 |
| `normalizer/` | 代码/市场/报告期/字段口径统一 | 标准化事实记录 | 抓取 |
| `master-data/` | 证券主数据：一码通映射、公司档案、行业分类映射 | `company_id` 唯一主体 | 行情/财务数值 |
| `quality/` | 完整性、一致性、时效性校验 | 质量报告 + 门禁结果 | 修复数据（只报告/隔离） |
| `analytics/leader` | 龙头识别与分层 | 龙头评分、行业内排名、档位 | 业务构成细节 |
| `analytics/segment` | 主营构成解析、占比校验、变化检测 | 分部收入/成本/毛利/占比 | 估值 |
| `analytics/policy` | 政策采集、增量识别、行业映射、扶持度/重要度打分 | 政策事件、行业权重 | 个股财务 |
| `analytics/valuation` | 分类估值 + 市场定价对比 | 估值区间、安全边际、观点标签 | 交易指令 |
| `api/` | REST 查询、证据链、人工复核写回 | JSON 响应 | 计算 |
| `web/` | 工作台 UI | 页面 | 业务逻辑 |

## 3. 技术选型（建议）

| 层 | 选型 | 理由 / 备选 |
|---|---|---|
| 采集 | Python 3.11 + `httpx`/`requests` + `selectolax` + `AkShare`（封装参考） | Python 生态对东财/巨潮接口封装最全；AkShare 作为**参考实现**而非强依赖，避免上游改版直接击穿 |
| 调度 | APScheduler（单点）→ Airflow（多任务依赖时） | 初期任务少，APScheduler 够用；任务间有 DAG 依赖后再上 Airflow |
| 存储 | PostgreSQL 15+（JSONB 字段存原始片段） | 窗口函数做行业内排名、JSONB 灵活存多口径字段；TimescaleDB 可选做行情时序扩展 |
| 缓存/锁 | Redis | 限流计数器、采集去重、幂等锁、热点查询结果 |
| 对象存储 | 本地文件系统 → MinIO/S3 | 原始 PDF/JSON 按 `source/dt/` 分区，只追加 |
| 计算 | Pandas/Polars + SQL；规则优先，LLM 仅做文本辅助 | 政策增量识别可用规则+人工复核，LLM 作辅助分类需留证据 |
| API | FastAPI + Pydantic | 类型校验强，便于把"来源/时点/口径"做成响应必填字段 |
| 前端 | Vue 3 + TypeScript + ECharts + TailwindCSS | 图表密集（估值分位、业务构成饼图、政策时间轴） |
| 部署 | Docker Compose（单机）→ K8s（可选） | 单机足够起步；采集器需可独立扩容与限速 |

## 4. 关键设计决策

### 4.1 统一证券主键 `company_id`
外部有至少 4 套代码体系，必须建映射表，禁止在业务表里直接存裸代码：

| 体系 | 形态 | 示例 |
|---|---|---|
| 本系统 | `SH600519` / `SZ000001` / `BJ430047` | 唯一主键 |
| 东财 push2 `secid` | `1.600519` / `0.000001`（沪=1，深/京=0） | 市场号搞错会**静默返回另一标的** |
| 东财 F10 `code` | `SH600519` | 与主键同形，需校验大小写 |
| 巨潮 `stock` | `000001,gssz0000001`（代码 + orgId） | orgId 必须 topSearch 反查，禁自拼 |
| Tushare `ts_code` | `600519.SH` | 可选源 |

> 采集入口强制校验"外部代码 → company_id"映射存在且市场号匹配；否则丢弃并告警，防止串标的。

### 4.2 三层数据视图
- **ODS（原始层）**：接口返回原样 + 采集元数据（`source`, `url`, `fetched_at`, `http_status`, `raw_hash`），只追加。
- **DWD（明细层）**：标准化后的事实表，一行一个"公司 × 报告期 × 口径 × 指标"。
- **DWS/ADS（汇总/应用层）**：龙头评分、行业政策权重、估值观点等，带 `model_version` 与 `as_of_date`，可整批重算。

### 4.3 证据链是一等公民
每个派生结论（龙头档位、政策加分、估值区间）都写入 `evidence` 表：`(claim_id, source_type, source_url, source_date, excerpt, confidence)`。前端任何数字点击可展开"这个数从哪来、怎么算的"。

### 4.4 配置驱动而非硬编码
评分权重、政策关键词、行业映射、估值方法选择规则全部放 `config/*.yaml` 并版本化。改权重 = 新 `model_version`，旧结果保留，支持 A/B 对比，禁止覆盖历史。

## 5. 部署与安全边界

```
[公网]  东方财富 / 巨潮 / 交易所 / 政策网站  （只读抓取，严格限速）
   │
[DMZ]   采集器（独立容器，出网白名单，不对外暴露）
   │
[内网]  PostgreSQL / Redis / 对象存储
   │
[内网]  API 服务 → Web 工作台（内网访问；如需公网，加鉴权+只读）
```

- 采集器与业务库分容器，采集器只写 ODS，不直接写 DWS。
- 对外不提供原始数据转售/分发；系统内展示需注明来源。
- 所有外部请求带 `User-Agent` 与合理 `Referer`，遵守 robots 与访问频率；设置熔断，连续失败立即退避而不是加大并发。

## 6. 与用户六步需求的对应

| 用户需求 | 承载模块 | 主要数据表 |
|---|---|---|
| ① 企业基本信息库 | `connector/em`, `master-data` | `company`, `company_identifier`, `company_profile` |
| ② 龙头识别 + 定时更新 | `analytics/leader` | `leader_score`, `leader_tier`, `evidence` |
| ③ 业务构成及占比 + 定时更新 | `analytics/segment` | `business_segment` |
| ④ 政策扶持度/重要度 + 权重 | `analytics/policy` | `policy_event`, `industry_policy_weight` |
| ⑤ 政策变化影响跟踪 | `analytics/policy` + 调度 | `policy_impact`, `impact_alert` |
| ⑥ 价值评估 + 市场比对 + 建议 | `analytics/valuation` | `valuation_result`, `investment_view` |
