# 03 — 数据模型设计

> 数据库：PostgreSQL 15+。命名：`dim_` 维度、`fact_` 事实、`ods_` 原始、`meta_` 元数据。  
> 通用约定：所有表带 `created_at`, `updated_at`；派生表带 `model_version`, `as_of_date`；金额单位"元"，比例小数。

## 1. 总体 ER 概览

```
dim_company ──┬─< dim_company_identifier
              ├─< fact_company_profile (SCD2)
              ├─< company_industry_map ──> dim_industry
              ├─< fact_financial ──> (利润/资产负债/现金流/指标)
              ├─< fact_business_segment
              ├─< fact_quote_snapshot
              ├─< fact_leader_score
              ├─< fact_valuation
              └─< fact_investment_view ──< evidence

dim_policy_document ──< policy_industry_impact ──> dim_industry
                    └─< policy_company_impact ──> dim_company

dim_industry ──< fact_industry_policy_weight
```

## 2. 主数据层

### 2.1 `dim_company`（证券主体，一司一行）

| 字段 | 类型 | 说明 |
|---|---|---|
| company_id | PK | `SH600519` / `SZ000001` / `BJ430047` |
| security_code | varchar(6) | 裸代码 |
| exchange | enum | SSE / SZSE / BSE |
| board | enum | 主板/创业板/科创板/北交所 |
| name_short | varchar | 简称 |
| name_full | text | 全称 |
| former_names | text[] | 曾用简称（防更名断链） |
| list_date / delist_date | date | 上市/退市日 |
| status | enum | 上市/退市/暂停 |
| currency | char(3) | CNY |
| created_at / updated_at | timestamptz | |

### 2.2 `dim_company_identifier`（外部代码映射）

| 字段 | 说明 |
|---|---|
| company_id | FK |
| source_code | `EM_PUSH2` / `EM_F10` / `CNINFO` / `TUSHARE` |
| external_code | `1.600519` / `SH600519` / `600519,gssz0000001` / `600519.SH` |
| external_orgid | 巨潮专用 |
| valid_from / valid_to | 支持代码变更历史 |

唯一约束 `(source_code, external_code)`。**采集时强制走此表反查**。

### 2.3 `fact_company_profile`（公司档案，SCD2 拉链）

关键字段：`legal_representative`, `chairman`, `actual_controller`, `controller_type`（国资/民营/外资/无实控人）, `employee_count`, `registered_capital`, `auditor`, `website`, `province`, `main_business` (text), `business_scope` (text), `issue_price`。

SCD2 字段：`valid_from`, `valid_to`, `is_current`。原因：实控人/审计机构变更是重要事件，需保留历史。

### 2.4 `dim_industry` + `company_industry_map`

行业分类必须**多口径并存**，禁止只存一套：

| scheme | 来源 | 用途 |
|---|---|---|
| `EM` | 东方财富行业 | 板块/成分股，更新快 |
| `CSRC` | 证监会行业 | 官方口径 |
| `SW` | 申万行业（如可得） | 专业研究口径，层级清晰 |
| `CUSTOM` | 本系统细分赛道 | 龙头识别与业务构成归集的最小粒度 |

`dim_industry`: `industry_id`, `scheme`, `level`(1/2/3), `parent_id`, `name`。  
`company_industry_map`: `company_id`, `industry_id`, `scheme`, `is_primary`, `effective_date`, `source`。一家公司可命中多个概念/赛道，但 `is_primary` 唯一。

## 3. 财务与行情事实层

### 3.1 `fact_financial`（统一财务事实表）

一行 = 一个公司 × 报告期 × 报表类型 × 指标：

| 字段 | 说明 |
|---|---|
| company_id, report_period, report_type | report_type: 合并/母公司 |
| period_type | 年报/半年报/一季报/三季报 |
| statement | income / balance / cashflow / indicator |
| metric_code | `OPERATE_INCOME` / `PARENT_NETPROFIT` / `ROE` / ... |
| value | numeric |
| unit | 元 / 比值 / 百分比（统一小数） |
| is_cumulative | 累计 or 单季（单季由累计倒推的标记 `derived=true`） |
| is_restated | 是否追溯调整 |
| source_code, source_url, source_date | 溯源 |

主键：`(company_id, report_period, report_type, statement, metric_code, source_code)`。

> 设计理由：宽表（一列一报告期）查询快但新增指标要改表；长表便于加指标、做口径对比。本期用长表，展示层用 `crosstab` 转宽。

### 3.2 `fact_quote_snapshot`

`company_id`, `trade_date`, `close`, `total_market_cap`, `float_market_cap`, `pe_ttm`, `pb`, `ps_ttm`, `dividend_yield_ttm`, `turnover_rate`, `source`。  
每个交易日一行；用于估值对比与市值排名。

### 3.3 `fact_business_segment`（业务构成）

| 字段 | 说明 |
|---|---|
| company_id, report_period | 报告期 |
| dimension | industry / product / region |
| segment_name | 分类名（原文） |
| segment_name_norm | 归一化名称（映射表后） |
| revenue, revenue_pct | 收入及占主营收入比 |
| cost, cost_pct | 成本及占比 |
| gross_profit, gross_profit_pct | 毛利及占比 |
| gross_margin | 毛利率 |
| yoy_revenue | 同比 |
| source_code, source_url, source_date | 溯源 |
| quality_flag | 占比异常等 |

主键：`(company_id, report_period, dimension, segment_name_norm, source_code)`。

## 4. 政策层

### 4.1 `dim_policy_document`

| 字段 | 说明 |
|---|---|
| policy_id | PK（hash: 发文机关+文号+标题） |
| title, doc_no | 标题、文号 |
| issuing_body | 发文机关 |
| level | 中央/国务院/部委/地方/监管 |
| issue_date, effective_date, expiry_date | 时点 |
| status | 征求意见/印发/实施/废止 |
| source_url, source_type | 原文链接；`official`/`media` |
| raw_text_hash | 去重 |
| category | 财税/产业/监管/科技/能源/... |
| increment_type | 首次提出/强度提升/范围扩大/工具明确/旧口径重复 |
| increment_score | 增量强度 0~1 |

### 4.2 `policy_industry_impact`

`policy_id`, `industry_id`, `relation_type`（直接/间接/概念映射）, `direction`（利好/利空/中性）, `strength_raw`, `evidence_excerpt`, `confidence`, `review_status`（自动/人工确认/人工驳回）, `reviewer`, `reviewed_at`。

### 4.3 `fact_industry_policy_weight`

| 字段 | 说明 |
|---|---|
| industry_id, as_of_date, model_version | 版本化 |
| support_score | 政策扶持度 0~100 |
| importance_score | 行业重要度 0~100 |
| composite_weight | 综合权重 0~1（用于估值加分） |
| driver_policy_ids | 主要贡献政策列表（JSONB） |
| calc_detail | 分项得分明细（JSONB） |

### 4.4 `policy_company_impact` + `impact_alert`

- `policy_company_impact`: `policy_id`, `company_id`, `impact_path`（收入/成本/估值/准入）, `direction`, `magnitude`, `horizon`（短期/中期/长期）, `rationale`, `confidence`。
- `impact_alert`: `company_id`, `policy_id`, `alert_type`, `created_at`, `read_status`。

## 6. 证据链与元数据

### 6.1 `evidence`（通用证据表）

| 字段 | 说明 |
|---|---|
| evidence_id | PK |
| claim_type | leader_tier / policy_weight / valuation / view |
| claim_ref | 对应记录主键 |
| source_type | official_filing / exchange / em_f10 / media / research |
| source_url | 可点击链接 |
| source_date | 数据时点（YYYY-MM-DD 或 YYYYQn） |
| excerpt | 原文摘录（≤500 字） |
| confidence | high / medium / low |

**规则**：任何进入 `fact_investment_view` 的关键结论，至少绑定 1 条 `source_type != media` 的证据；否则 `confidence` 强制为 low。

### 6.2 元数据表

- `ods_fetch_log`: 每次抓取的 `raw_hash`, `url`, `status`, `row_count`, `duration_ms`。
- `data_quality_report`: 表名、检查项、通过率、异常样本、时间。
- `model_version_registry`: 版本号、权重配置 hash、生效时间、备注。
- `review_queue`: 人工复核任务、`status`、`assignee`、`decision`。

## 7. 关键约束与索引

```sql
-- 证券映射唯一性
UNIQUE (source_code, external_code) ON dim_company_identifier;

-- 财务事实幂等
UNIQUE (company_id, report_period, report_type, statement, metric_code, source_code)
  ON fact_financial;

-- 版位唯一：同一天同版本只一条
UNIQUE (company_id, as_of_date, model_version) ON fact_leader_score;
UNIQUE (company_id, as_of_date, model_version) ON fact_valuation;

-- 常用索引
CREATE INDEX idx_fin_metric ON fact_financial (metric_code, report_period);
CREATE INDEX idx_seg_period ON fact_business_segment (report_period, dimension);
CREATE INDEX idx_quote_date ON fact_quote_snapshot (trade_date, total_market_cap DESC);
CREATE INDEX idx_evidence_claim ON evidence (claim_type, claim_ref);
CREATE INDEX idx_policy_date ON dim_policy_document (issue_date, level);
```

## 8. 版本与重算策略

- 派生表（leader/valuation/view/policy_weight）按 `as_of_date + model_version` 分区写，**不覆盖**旧版本。
- 修改权重配置 → 新 `model_version` → 全量重算最近 N 期 → 对比新旧差异 → 人工确认后切换"当前版本"。
- 原始层只读；重算永远从 DWD 开始，不从展示层倒推。
- 退市/更名公司保留主体，`status` 变更，历史评分不删除。
