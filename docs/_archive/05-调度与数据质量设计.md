# 05 — 调度与数据质量设计

## 1. 更新频率总表

| 数据/计算 | 频率 | 触发时间（北京时间） | 说明 |
|---|---|---|---|
| 证券列表 `sync_security_master` | 每周 | 周一 08:00 | 新股/退市/更名 |
| 公司档案 `sync_company_profile` | 每周 | 周六 02:00，分批 | 低频静态数据 |
| 行情快照 `sync_quote_snapshot` | 每交易日 | 15:30（收盘后） | 需判断交易日，非交易日跳过 |
| 公告增量 `sync_announcements` | 每日 | 07:00 / 18:00 | 定期报告发布高峰加密 |
| 财务数据 `sync_financials` | 财报季每日 | 18:30 | 1~4 月、7~9 月加密；其余每周 |
| 业务构成 `sync_business_segment` | 年报/中报后 | 公告触发 + 每周兜底 | 季报一般不披露 |
| 政策文件 `sync_policy_docs` | 每日 | 07:30 | 白名单栏目 |
| 龙头评分 `calc_leader` | 财报后 + 每周 | 20:00 | 依赖财务/业务/行情 |
| 政策权重 `calc_policy_weight` | 政策命中后 + 每周 | 20:30 | 依赖政策映射 |
| 价值评估 `calc_valuation` | 每周 | 21:00 | 依赖以上全部 |
| 观点合成 `publish_view` | 每周 | 人工复核后发布 | 不自动对外发布 |
| 质量巡检 `quality_check` | 每日 | 22:00 | 全库扫描 |

> **时间口径**：A 股交易时段 09:30-11:30 / 13:00-15:00（北京时间）。收盘后取数才是一日完整快照；盘中取数必须标"盘中快照"，不与收盘价混用。财报按**披露日（北京时间）**触发，报告期按期末日入库，两者分开。

## 2. 任务依赖 DAG

```
sync_security_master
   └─> sync_company_profile ──┐
                              ├─> calc_leader ──┐
sync_announcements ──┬─> sync_financials ───────┤
                     └─> sync_business_segment ─┤
                                                ├─> calc_valuation ─> review_queue ─> publish_view
sync_quote_snapshot ─────────────────────────────┤
sync_policy_docs ─> policy_impact ─> calc_policy_weight ─┘
```

- 上游任务失败 → 下游任务标记 `blocked`，不跑半截数据。
- 允许"降级运行"：上游仅部分公司失败且覆盖率 ≥ 95% 时，下游可跑，但结果标 `partial=true`。
- 依赖实现：初期用 APScheduler + 状态表轮询；任务多后迁 Airflow。

## 3. 幂等与可重算

| 机制 | 实现 |
|---|---|
| 任务幂等键 | `(task_name, as_of_date, source_code, scope)`，Redis SETNX 加锁，TTL 2h |
| 抓取去重 | `(external_key, params_hash, dt)` 命中缓存则跳过 HTTP |
| 写入策略 | 事实表 `ON CONFLICT DO UPDATE`（限值变化才更新）；原始层只 `INSERT` |
| 重算 | 删除/重建目标 `as_of_date + model_version` 分区，不影响其他版本 |
| 失败重试 | 连接器层指数退避；任务层失败进 `failed_queue`，支持单任务手动重跑 |
| 断点续跑 | 全市场分批任务记录 `last_completed_batch`，重启后从断点继续 |

## 4. 数据质量规则（门禁）

分三层，严重度不同：

### 4.1 硬门禁（不通过则阻断下游）

| 检查 | 阈值 |
|---|---|
| 证券主数据映射 | 采集记录中无法映射 `company_id` 的比例 = 0 |
| 关键字段完整性 | 核心龙头池的营收、归母净利、总资产、市值缺失率 ≤ 5% |
| 报告期合法性 | 期末日必须是季度末（03-31/06-30/09-30/12-31） |
| 数值合法性 | 收入 ≥ 0；市值 > 0；占比 ∈ [0,1]；毛利率 ∈ [-1,1] |
| 业务构成占比 | 同维度 Σ占比 与 100% 偏差 ≤ 2pct |
| 行情时点 | 快照日期必须是交易日且 ≤ 当前日期 |

### 4.2 软门禁（标记但不阻断）

- 接口返回行数较上期下降 > 30% → `quality_flag=row_drop`，进复核队列。
- 行业分类变更、实控人变更、审计机构变更 → 生成事件，重评龙头/估值。
- 归母净利润与净利润差异 > 20% → 标记检查少数股东损益。
- 单季指标由累计倒推得到 → 标 `derived=true`。
- 业务结构 L1 变化 > 15pct → 结构突变预警。

### 4.3 一致性交叉校验

- 同一指标两个来源（如东财 F10 vs 业绩报表）差异 > 5% → 记录分歧，优先一手源，取不到一手源则标 `confidence=low`。
- 市值 ≈ 总股本 × 收盘价，偏差 > 5% → 检查股本口径（总股本 vs 流通股本）。
- 龙头评分与上一期排名变动 > 10 位 → 必须写变更原因。

## 5. 监控与告警

| 告警类型 | 条件 | 通道 |
|---|---|---|
| 连接器熔断 | 连续失败 10 次 | 站内消息 + 日志 |
| 数据超时 | 应更新表的最新 `as_of_date` 落后预期 1 天以上 | 站内消息 |
| 质量门禁失败 | 任一硬门禁不通过 | 阻断下游 + 站内消息 |
| 观点待复核 | `review_queue` 新增 | 站内消息 |
| 政策重大影响 | `impact_alert` 中 `magnitude=high` 或核心龙头命中 | 站内消息 |

监控面板展示：各源成功率、最近抓取时间、覆盖率、质量通过率、任务耗时趋势、待复核数量。

## 6. 数据保鲜期（SLA）

| 数据 | 最大保鲜期 | 超时处理 |
|---|---|---|
| 行情快照 | 1 个交易日 | 停止展示"最新估值"，改显"截至 YYYY-MM-DD" |
| 财务数据 | 1 个季度（配合披露节奏） | 标"财报可能未更新" |
| 业务构成 | 6 个月 | 业务结构相关结论降级 |
| 政策文件 | 1 天 | 政策权重按衰减因子自动降权 |
| 公司档案 | 3 个月 | 不影响计算，标"档案可能过期" |

任何页面在展示结论时，若其依赖数据已超保鲜期，必须在显著位置提示数据截止日期，不得伪装成实时结论。
