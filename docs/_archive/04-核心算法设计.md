# 04 — 核心算法设计

> 本文定义四个计算模块的可执行规则。**所有阈值、权重都是可调参数（放在 config，版本化）**，不是"正确值"，需要用历史回测和人工复核持续校准。  
> 任何模块的输出都带 `confidence`；缺关键输入时不强行出分，返回"数据不足"。

---

## 0. 通用约定

- **行业内排名**用百分位：`pct_rank = (排名 - 1) / (样本数 - 1)`，越大越靠前。
- **样本清洗**：剔除上市不满 1 年（避免次新扰动）、ST/*ST（异常状态单独标记）、报告期缺失 > 1 期的标的；被剔除的公司进入"观察池"，仍保留数据但不参与评分排名。
- **去极值**：所有参与评分的原始指标先做行业内的 winsorize（1% / 99% 分位截断），再标准化。
- **标准化**：`z = (x - 行业中位数) / 行业IQR` 或直接用百分位；本期建议用**百分位**，对异常值更稳健。
- **周期行业**（钢铁、煤炭、化工、航运、半导体制造等）：盈利指标用 **5 年中位数**而非单年，避免周期顶部把周期股误判为龙头。
- **口径**：净利润统一用归母净利润；ROE 用摊薄；市值用总市值。

## 1. 龙头企业识别（模块 `analytics/leader`）

### 1.1 设计思路

"龙头"是**行业内相对地位**，不是绝对数值。因此所有指标都在**细分赛道（CUSTOM 行业）内**做横向比较。评分由 5 个维度合成：

| 维度 | 权重 | 指标（行业百分位） | 理由 |
|---|---:|---|---|
| 规模 `scale` | 25% | 营业收入、总资产、总市值（各 1/3） | 龙头首先得"大"，市值代表市场认可 |
| 盈利 `profit` | 25% | 归母净利润、ROE、毛利率（各 1/3） | 大而不强不是龙头 |
| 成长 `growth` | 20% | 营收 3 年 CAGR、归母净利 3 年 CAGR（各 1/2） | 龙头要有扩张性，周期行业用 5 年中位数口径 |
| 地位 `position` | 20% | 主营构成中第一大业务占比的合理性、行业排名、产业链卡点标记 | 见 1.2 |
| 稳定性 `stability` | 10% | 盈利波动率（近 5 年净利增速标准差倒数）、审计意见、实控人稳定性 | 排除"一次性利润"和治理风险 |

```
score = 100 × Σ (w_i × 维度得分_i)
```

### 1.2 地位分 `position` 的特殊处理

地位分不能只靠财务数据，需要"补齐信息"：

1. **规模位次**：营收/净利/市值在细分赛道的排名百分位（自动）。
2. **市占率代理**：优先用公开披露的市占率（年报/券商研报引用，标 `source_type=research`，需核实原文）；无市占率数据时用**营收排名百分位作为代理**，并把 `confidence` 降为 medium，在前端明示"代理指标"。
3. **产业链卡点**：由 `policy_industry_impact` 与人工维护的"赛道卡点清单"提供布尔标记（如"具备核心工艺/资质/客户绑定"），命中加分。此项必须有证据，否则不计。
4. **业务纯度**：第一大业务收入占比在 40%~85% 之间给满分（专注主业），过高（单一依赖）或过低（业务散乱）扣分，**通过业务构成模块计算**。

> **不做的事**：不用股价涨幅、涨停次数、龙虎榜数据判定龙头。那是情绪龙头，与本系统定义不同。

### 1.3 分层规则

| 档位 | 规则 |
|---|---|
| 核心龙头 | `score ≥ 75` 且 至少 3 个维度得分 ≥ 60 且 `confidence = high` |
| 候选龙头 | `60 ≤ score < 75`，或 `score ≥ 75` 但缺关键数据导致 `confidence = medium` |
| 观察标的 | `40 ≤ score < 60`，或行业内排名前 30% 但上市不满 1 年 |
| 非龙头 | 其余 |

行业内**核心龙头数量上限**：默认每赛道不超过 3 家（防止龙头泛滥），按分数取前 3；若第 4 名与第 3 名分差 < 3 分则并列保留。该上限可配置。

### 1.4 更新触发与降级

- 财报披露后（由公告事件触发）→ 重算相关公司及同赛道全部公司。
- 行情快照每日更新只影响 `scale` 中的市值项，可增量刷新；财务项不变。
- 数据源缺失：某维度缺失 > 50% 指标 → 该维度不参与归一化，权重按比例分摊到其他维度，并标记 `imputed=true` + `confidence` 降级。
- 输出写入 `fact_leader_score`，附 `calc_detail` 记录每项原始值与百分位。

### 1.5 反向校验（每期必做）

- 核心龙头名单与上一期对比，新增/掉出必须给出**可解释原因**（如"营收 CAGR 从 30% 降至 5%"），写入变更日志；无法解释则标记 `review_required`。
- 抽检：随机 3 家核心龙头，人工核对行业地位是否与常识一致，不一致时检查行业映射与权重配置。

## 2. 业务构成解析（模块 `analytics/segment`）

### 2.1 输入与解析

主源：东财 F10 `BusinessAnalysis/PageAjax` 的 `zygcfx`；核对源：巨潮年报 PDF（二期实现）。

解析步骤：

1. 按 `报告期` 分组，只保留年报与中报（季报通常不披露分部数据）。
2. 按 `dimension` 分三类：行业 / 产品 / 地区。
3. 对 `segment_name` 做归一化（同义词映射 + 人工映射表），生成 `segment_name_norm`；新出现的分类名进入待确认队列。
4. 校验：同一报告期、同一维度下，`Σ revenue_pct ≈ 100%`（容差 ±2%）；`revenue / revenue_pct ≈ 主营收入总额`。异常标 `quality_flag` 并排除出计算。
5. 冲突处理：同一期 F10 与年报 PDF 数字不一致时，**以年报为准**，记录差异。

### 2.2 派生指标（供龙头识别与估值使用）

| 指标 | 计算 | 用途 |
|---|---|---|
| `top1_pct` | 第一大分部收入占比 | 业务纯度、单一依赖风险 |
| `hhi` | Σ(收入占比²) | 业务集中度，>0.25 视为高集中 |
| `segment_growth_i` | 分部收入同比 | 找增长引擎 |
| `segment_margin_i` | 分部毛利率 | 找利润引擎（收入占比高 ≠ 利润贡献高） |
| `profit_contribution_i` | 分部毛利 / Σ分部毛利 | 真正的主业结构 |
| `structural_change` | 本期 vs 上期收入占比向量 L1 距离 | 业务结构突变预警（>15pct 触发） |

### 2.3 输出

- 明细写入 `fact_business_segment`。
- 摘要写入个股档案：`现金牛业务`（收入占比高、增速低、毛利稳）、`增长引擎`（增速前 2 且收入占比 > 10%）、`边缘业务`（收入占比 < 5%）。
- 结构突变 → 触发 `impact_alert`，提示"业务结构变化，需重评龙头地位与估值方法"。

## 3. 政策扶持度与行业重要度（模块 `analytics/policy`）

### 3.1 采集与增量识别

政策价值在**增量**，不复述原文。对每篇采集到的政策文本，规则引擎判断 `increment_type`：

| 类型 | 判据（关键词 + 模式） | 基础分 |
|---|---|---:|
| 首次提出 | 新概念/新清单首次出现在该发文机关文件 | 1.0 |
| 强度提升 | "由鼓励改为强制""提高补贴标准""纳入考核"等 | 0.9 |
| 范围扩大 | "扩大试点""新增X行业/地区" | 0.7 |
| 工具明确 | 出现具体财政/税收/采购/信贷工具与金额 | 0.8 |
| 旧口径重复 | 与既有文件内容高度重合（相似度 > 0.85） | 0.1 |

**不把新闻当政策**：只有官方站点正式发布（有发文机关 + 文号/发布日期）的文件进入 `dim_policy_document`；媒体解读只作 `source_type=media` 证据，不单独形成政策事件。

### 3.2 扶持度 `support_score`（0~100）

对每个"政策 × 行业"命中记录：

```
impact_raw = L × T × E × S × D × increment_score
```

| 因子 | 取值 | 说明 |
|---|---|---|
| `L` 政策级别 | 国务院/中央 1.0；部委 0.8；省级 0.5；监管/协会 0.3 | 顶层力度大但落地慢，部委落地快 |
| `T` 执行工具 | 财政补贴/政府采购 1.0；税收优惠 0.8；信贷支持 0.8；准入放松 0.7；标准制定 0.6；鼓励倡议 0.3 | "产业鼓励"≠"产业补贴" |
| `E` 明确性 | 点名行业/企业 1.0；列举范围 0.7；泛泛表述 0.3 | |
| `S` 执行阶段 | 已实施/细则出台 1.0；正式印发 0.8；征求意见 0.5；规划目标 0.4 | |
| `D` 时效衰减 | 发布 90 天内 1.0；90~365 天线性衰减至 0.5；>1 年 0.3 | 政策热度会衰减 |

```
行业 support_score = 100 × tanh( Σ impact_raw / K )   # K 为归一化常数，默认 3.0
```

`tanh` 压缩避免多份政策叠加后爆表；`K` 可配置。

### 3.3 重要度 `importance_score`（0~100）

衡量行业本身的战略地位，与当期政策热度无关：

| 因子 | 权重 | 数据来源 |
|---|---:|---|
| 产业规模（营收/增加值占比） | 30% | 统计公报、行业年鉴（人工维护或公开数据） |
| 国家战略清单命中（战略性新兴产业、专精特新、"卡脖子"清单等） | 30% | 官方清单，人工维护映射 |
| 产业链卡点属性（上游断供风险、国产替代空间） | 25% | `industry-chain` 人工标注 + 证据 |
| 就业/税收贡献 | 15% | 统计公报（可得则用，不可得则权重分摊） |

**拿不到数据的因子不估算**，权重按比例分摊到其他因子，并记录 `data_gap`。

### 3.4 综合权重 `composite_weight`

```
composite_weight = clip( w_p × support_score + w_i × importance_score , 0, 100 ) / 100
默认 w_p = 0.6, w_i = 0.4
```

- 上限：默认 0.25（避免单一行业政策溢价过高）。
- `relation_type = 概念映射` 的命中，权重乘 0.3 且不计入核心龙头加分。
- 监管/利空政策：`direction = negative`，产生 `risk_penalty` 而非加分。
- 全部结果写 `fact_industry_policy_weight`，附 `driver_policy_ids` 与 `calc_detail`。

### 3.5 政策变化 → 企业影响跟踪

1. 新政策入库 → 解析命中的行业（直接/间接/概念）。
2. 通过 `company_industry_map` 找到该行业的**核心龙头与候选龙头**（非全市场，控制噪音）。
3. 生成 `policy_company_impact`，判断传导路径：`收入（需求/订单/价格）`、`成本（补贴/税负/原料）`、`准入（资质/牌照）`、`估值（主题溢价）`。
4. 每条影响必须有 `rationale` 与 `evidence_excerpt`；无量化依据时标 `magnitude=unknown`，**不编数字**。
5. 触发 `impact_alert` 推送到工作台；同一政策 7 天内不重复推送同一公司。
6. **交易阶段标记**（研究参考，不是操作建议）：`政策催化初期 / 已提前预期 / 利好兑现中 / 等待实施细则`。判断依据：政策发布日期、相关板块估值分位变化、成交额变化；依据不足标"未知"。

## 4. 价值评估与投资观点（模块 `analytics/valuation`）

### 4.1 公司类型判定（决定估值方法）

| 类型 | 判据 | 主方法 | 辅助方法 |
|---|---|---|---|
| 高成长 | 营收 CAGR ≥ 20% 且 ROE ≥ 12% | PEG、PS、EV/EBITDA | DCF（高增长期） |
| 稳健成长 | CAGR 10~20%，ROE 稳定 ≥ 10% | PE、PEG | DCF |
| 周期 | 净利波动率 > 阈值或属周期行业清单 | PB、周期中枢 PE | 产能/价格拐点 |
| 价值 | 增速 < 10%，分红稳定、低 PB | PE、PB、股息率 | DDM |
| 平台/金融 | 平台型或金融行业 | SOTP、DCF、P/AUM | 分部估值 |

类型判定结果写入 `fact_valuation.company_type`，并给出置信度；边界公司允许多方法并列，取**加权区间**而非单选。

### 4.2 估值区间计算（区间，不给单点目标价）

每种方法先算一个内在价值区间 `[low, high]`，再按方法权重合成：

```
intrinsic_base = Σ (method_weight_j × method_value_j)
intrinsic_low  = min(各方法 low) 与 base×0.85 的较大者
intrinsic_high = max(各方法 high) 与 base×1.15 的较小者
```

- **历史分位法**：取近 10 年 PE/PB 分位（数据不足则降级为 5 年并标注）；30% 以下偏低、30~70% 中性、70% 以上偏高。
- **行业横向**：同细分赛道、同类型公司对比，先核对财年口径。
- **DCF（如适用）**：WACC 8%~12%，永续增长率 2%~3%，必须做 Bear/Base/Bull 三情景；终值占比 > 70% 时标 `terminal_heavy=true` 并降低置信度；**不把单一情景当目标价**。
- **PEG**：`PE / (净利增速×100)`，增速用未来 2~3 年一致预期（无预期数据时用历史 CAGR 并标注）。

### 4.3 与市场定价对比

```
margin_of_safety = (intrinsic_base - market_price) / intrinsic_base
price_vs_band    = market_price / intrinsic_base - 1
```

同时看：① 相对内在价值的安全边际；② 自身历史估值分位；③ 同业横向分位。三者方向一致才给高置信度。

> **关键**：必须拆解"当前股价里已经包含了什么"。若高估值对应高增速与政策催化，可能是合理定价；若低估值伴随增速下修与治理风险，可能是价值陷阱。该判断写入 `key_assumptions`，由规则 + 人工复核生成，不让模型自由发挥。

### 4.4 投资观点合成（评级，不是指令）

```
view_score = 50% × value_score       # 安全边际 + 估值分位
           + 20% × quality_score     # 龙头评分/5 + 盈利质量
           + 15% × policy_bonus      # 所属行业 composite_weight
           + 15% × growth_score      # 3 年 CAGR 与预期兑现
           - risk_penalty            # 治理/审计/单一客户/政策利空/高杠杆
```

| `view_score` | 评级 |
|---|---|
| ≥ 80 | 显著低估 |
| 65~80 | 低估 |
| 45~65 | 合理 |
| 30~45 | 偏高 |
| < 30 | 高估 |

**输出三件套**（缺一不发布）：

1. `rating` + `confidence`（高/中/低）；
2. `key_assumptions`（3~5 条，每条可追溯来源）；
3. `counter_signals`（反证/失效信号，如"若连续两季营收增速 < X% 则逻辑失效"）。

**硬约束**：
- 系统**不输出**买入/卖出/持有指令、目标价点位、仓位比例。评级是"价值偏离度"的研究标签。
- `confidence = low` 或缺少一手证据时，前端只显示"观察"，不显示评级。
- 任何页面展示投资观点必须同时展示免责声明与数据时点。
- 观点生成后进入 `review_queue`，人工确认才置 `published=true`；未确认仅内部可见。

### 4.5 回测与校准（上线前必做）

- 用历史时点重建观点（`as_of_date` 切片），比较各评级分组的未来 6/12 个月收益分布，验证评级是否有区分度。
- 检查"显著低估"组是否集中在某一行业/某一类风格（避免系统性偏差）。
- 龙头识别回测：核心龙头名单在未来 1 年的营收/净利增速是否显著优于行业中位数；若不显著，回看 `position` 与权重设置。
- 每次权重调整产生新 `model_version`，对比新旧结果，禁止静默覆盖。

## 5. 模块间调用关系（一次完整更新）

```
公告触发 / 定时触发
   │
   ├─ sync_financials → fact_financial
   ├─ sync_business_segment → fact_business_segment → 结构突变告警
   ├─ analytics/leader（读财务 + 业务构成 + 行情）→ fact_leader_score
   ├─ sync_policy_docs → dim_policy_document
   │     └─ 增量识别 → policy_industry_impact → fact_industry_policy_weight
   │           └─ policy_company_impact → impact_alert
   └─ analytics/valuation（读财务 + 行情 + 龙头分 + 政策权重）
         → fact_valuation → fact_investment_view → review_queue → 发布
```

**顺序不可颠倒**：估值依赖龙头分与政策权重；政策影响依赖行业映射；业务构成依赖定期报告入库。调度层用 DAG 保证依赖，见 `05-调度与数据质量设计.md`。
